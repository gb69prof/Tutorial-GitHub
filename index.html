Tutorial – Creare una web app con ChatGPT e pubblicarla su GitHub

Dal testo di Freud alla pubblicazione online: guida passo passo per docenti e studenti.

1. Progetto di base 2. ChatGPT & testo 3. Immagini, video, mappa 4. Web app & ZIP 5. GitHub – ZIP & repository 6. GitHub – file & cartelle 7. Immagini su GitHub 8. Pubblicare con GitHub Pages

PRIMA PARTE – Il progetto

Parte 1 — Creare il progetto di base della web app (solo testo)

La web app che vogliamo costruire parte da un’unica cosa: il testo del documento Freud.pdf che useremo come base concettuale. In questa prima fase non esistono immagini, video, mappe o codice. Esiste solo il contenuto da riorganizzare.

L’obiettivo è semplice: preparare il materiale testuale che entrerà nella web app.

Per farlo occorre:

  1. Estrarre dal PDF i concetti fondamentali:
    • Introduzione su Freud e sulla sua visione della mente;
    • Sezione sull’Es;
    • Sezione sull’Io;
    • Sezione sul Super-Io.
  2. Riscrivere questi contenuti in forma chiara, didattica e destinata agli studenti.
  3. Mantenere la fedeltà al testo, ma con una struttura coerente a una web app.

La Prima Parte, quindi, serve solo a produrre il testo che verrà poi inserito nel sito. Nessun codice. Nessun file HTML. Nessuna immagine.

Parte 2 — Preparare ChatGPT a leggere il documento e riscrivere il testo

Una volta scelto il materiale, bisogna istruire ChatGPT affinché:

  1. legga il PDF,
  2. riconosca le sezioni,
  3. riscriva solo il testo necessario per le quattro sezioni della web app.

Il tutorial deve fornire un prompt chiaro, ad esempio:

«Ti allego un documento PDF su Freud. Voglio che tu lo legga e che estragga TUTTI i contenuti necessari per creare le sezioni della web app: Introduzione – Es – Io – Super-Io. Riscrivi questi contenuti in forma sintetica e didattica. In questa fase devi produrre solo testo, senza immagini, senza video, senza mappe, senza codice. Questo materiale verrà usato nella fase successiva per costruire il sito.»

Questa seconda parte serve a una cosa sola: preparare un documento conclusivo che conterrà tutti i testi già riscritti. E questo documento (solo testo) verrà allegato nella Fase 3, quando ChatGPT genererà:

  • index.html
  • style.css
  • script.js
  • struttura della cartella della web app

Parte 3 – Inserire immagini, video e geolocalizzazione nella web app

Questa parte del lavoro serve per preparare tutto il materiale multimediale prima che ChatGPT generi il codice finale della web app. In questa fase non si crea ancora l’HTML: si forniscono all’IA tutti gli elementi che dovrà inserire.

1. Allegare le immagini

Per usare le immagini nella web app, devi prima allegarle direttamente a ChatGPT.

  1. Scegli le immagini.
  2. Rinominale in modo semplice (es. es.jpg, io.jpg, superio.jpg).
  3. Preparale per essere inserite nella cartella assets/.
  4. Allegale alla chat.

Nel tutorial va scritto così:

«Allega ora a ChatGPT tutte le immagini che vuoi inserire nella web app. I file saranno collocati nella cartella assets/, che sarà creata automaticamente nella fase di generazione del codice.»

Senza questo allegato, l’IA non potrà inserirle nell’HTML.

2. Inserire un video YouTube

Ci sono due modi per far inserire un video YouTube nella web app:

Metodo A: incollare l’URL

È il modo più rapido. Incolli il link del video, e ChatGPT genererà la sezione video usando un iframe standard.

Metodo B: incollare il codice di incorporamento (embed)

È il metodo più preciso. Su YouTube:

  • apri il video;
  • clicca su Condividi;
  • seleziona Incorpora;
  • copia tutto il codice <iframe> … </iframe>.

Il testo del tutorial:

«Per inserire un video, incolla nella chat l’URL di YouTube oppure il codice di incorporamento. ChatGPT aggiungerà automaticamente l’iframe nella sezione dedicata ai video.»

3. Preparare la geolocalizzazione (Vienna)

Per inserire una mappa nella web app serve un solo dato essenziale: le coordinate del luogo da visualizzare. Nel nostro caso useremo Vienna:

  • Latitudine: 48.2082
  • Longitudine: 16.3738

Il testo del tutorial:

«Indica a ChatGPT le coordinate geografiche del punto che vuoi mostrare nella mappa. Per Vienna usa: latitudine 48.2082, longitudine 16.3738. L’IA userà questi valori per generare la sezione della mappa.»

Parte 4 — Far generare a ChatGPT la web app completa (file ZIP finale)

In questa fase hai già tutto ciò che serve:

  • il testo tratto dal documento Freud.pdf;
  • le immagini allegate e rinominate correttamente;
  • i video YouTube (link o codici di incorporamento);
  • le coordinate geografiche (nel nostro caso Vienna: 48.2082, 16.3738).

Adesso si passa al punto cruciale: dire a ChatGPT di usare autonomamente questi materiali per costruire la web app completa e consegnarla in un file ZIP.

1. Dare a ChatGPT tutti gli elementi prima della richiesta finale

Prima della richiesta definitiva devi assicurarti che l’IA abbia:

  • il documento con i testi della web app (già puliti e riscritti);
  • le immagini allegate nella chat;
  • i video (URL o iframe);
  • le coordinate della mappa.

Solo quando tutti questi materiali sono presenti nella conversazione, puoi passare alla richiesta finale.

2. La richiesta finale da usare su ChatGPT

Il punto del tutorial è dare agli studenti/docenti una frase chiara, che può essere copiata e incollata. Eccola:

«Ora crea la web app completa usando TUTTI i materiali che ti ho fornito. Genera tre file: index.html con testo, immagini, video e mappa; style.css con lo stile della pagina; script.js con il codice per la mappa e le funzioni interattive. Crea anche la cartella assets/ e inserisci i nomi delle immagini che ti ho allegato. Organizza tutto in un’unica struttura di progetto pronta per essere compressa. Quando hai generato tutti i file, consegnami il pacchetto in un file ZIP scaricabile.»

Con questa istruzione:

  • ChatGPT usa il testo per riempire automaticamente le sezioni (introduzione, Es, Io, Super-Io);
  • inserisce le immagini nel punto logico del testo;
  • colloca i video nella sezione video, costruendo l’iframe;
  • genera la geolocalizzazione usando le coordinate di Vienna;
  • prepara index.html, style.css, script.js e la cartella assets/;
  • impacchetta tutto in uno ZIP pronto da caricare su GitHub.

3. Come ChatGPT deve consegnare lo ZIP

Il tutorial deve specificare ciò che l’IA deve fare:

«Una volta creati i tre file e la cartella assets, genera un file ZIP contenente l’intera struttura della web app. Fornisci il link per scaricare lo ZIP direttamente dalla chat.»

In questo modo l’utente riceve subito una struttura del tipo: 

freud-es-io-superio/
│
├── index.html
├── style.css
├── script.js
└── assets/
      ├── es.jpg
      ├── io.jpg
      └── superio.jpg

Seconda parte – Scaricare il tutto in GitHub

Parte 1 – Caricare la web app su GitHub (prima fase)

Questa fase del tutorial spiega come portare la web app generata da ChatGPT dentro GitHub, per poi renderla pubblica.

1. Decomprimere la cartella ZIP

Dopo aver ricevuto da ChatGPT il file ZIP della web app:

  1. scaricalo sul computer;
  2. fai clic con il tasto destro;
  3. scegli “Estrai” o “Decomprimi”.

Otterrai una cartella con dentro tutti i file del progetto:

index.html
style.css
script.js
assets/

È questa cartella che devi caricare su GitHub.

2. Creare un nuovo progetto (repository) su GitHub

Per inserire la web app online, bisogna prima crearle una “casa” dentro GitHub. I passaggi:

  1. vai su github.com ed effettua l’accesso;
  2. in alto a destra clicca su +;
  3. scegli New repository;
  4. assegna un nome al progetto (es. freud-es-io-superio);
  5. lascia il repository Public (necessario per pubblicarlo online);
  6. non aggiungere file o template (no README, no .gitignore);
  7. clicca su Create repository.

Parte 2 – Inserire i file della web app in GitHub

Una volta creato il repository vuoto su GitHub e decompressa la cartella ZIP della web app, si passa all’inserimento dei file nel progetto.

1. Caricare i file principali (index.html, style.css, script.js)

Questi sono i tre file fondamentali della web app. Vanno caricati direttamente nella root del repository.

  1. Apri il repository su GitHub.
  2. Clicca su Add file.
  3. Seleziona Upload files.
  4. Trascina i tre file nella finestra: 
    index.html
style.css
script.js
  5. Scorri in basso e clicca Commit changes.

2. Creare una cartella per le immagini (metodo .gitkeep)

GitHub non permette di creare una cartella vuota: per questo si usa un file “segnaposto”, chiamato .gitkeep, che serve esclusivamente a far comparire la cartella nel repository.

  1. Nel repository, clicca Add file → Create new file.
  2. Nella casella del nome del file scrivi: assets/.gitkeep
  3. Lascia il file vuoto.
  4. Clicca Commit changes.

Parte 3 – Inserire le immagini nella cartella assets su GitHub

Dopo aver creato la cartella assets tramite il file .gitkeep, bisogna caricare le immagini della web app all’interno di quella cartella. Questa operazione si fa direttamente dal repository GitHub.

1. Aprire la cartella assets

  1. Vai nel tuo repository su GitHub.
  2. Clicca sulla cartella assets. Al suo interno vedrai solo il file .gitkeep.

2. Caricare le immagini

  1. Dentro la cartella assets, clicca su Add file.
  2. Seleziona Upload files.
  3. Trascina qui tutte le immagini usate dalla web app (es. es.jpg, io.jpg, superio.jpg).
  4. Scorri in basso e clicca Commit changes.

A caricamento completato, la struttura del repository deve apparire così:

freud-es-io-superio/
│
├── index.html
├── style.css
├── script.js
└── assets/
      ├── .gitkeep
      ├── es.jpg
      ├── io.jpg
      └── superio.jpg

Parte finale – Pubblicare la web app con GitHub Pages

Una volta caricati tutti i file del progetto nel repository — compresi index.html, style.css, script.js e la cartella assets con le immagini — l’ultimo passo è rendere la web app visibile online tramite GitHub Pages.

1. Aprire le impostazioni del repository

  1. Entra nel repository della tua web app.
  2. In alto, clicca su Settings.
  3. Nel menu laterale, scorri fino alla voce Pages (sezione “Code and automation”).

Questa sezione permette di pubblicare la web app come sito.

2. Attivare GitHub Pages

Nella sezione “Pages”:

  1. Trova la voce Build and deployment.
  2. Nella tendina Source, seleziona Deploy from a branch.
  3. Compariranno due nuove tendine:
    • Branch
    • Folder
  4. Imposta così:
    • Branch: main
    • Folder: / (root)
  5. Clicca Save.

GitHub inizierà a generare la pagina.

3. Attendere la pubblicazione

Dopo qualche secondo comparirà un messaggio di conferma con il link del sito, del tipo: 

https://tuo-nome.github.io/nome-del-repository

Questo è l’indirizzo pubblico della web app. Se non compare subito, aggiorna la pagina dopo 20–30 secondi: GitHub Pages impiega un attimo a costruire il sito.

4. Verifica finale

Apri il link generato. Dovresti vedere la tua web app perfettamente online, con:

  • testi;
  • immagini;
  • video;
  • mappa.

Se qualcosa non appare, di solito le cause sono:

  • nome errato delle immagini;
  • file caricati nella cartella sbagliata;
  • struttura delle cartelle modificata accidentalmente.

In quel caso basta correggere e GitHub aggiornerà automaticamente il sito.
